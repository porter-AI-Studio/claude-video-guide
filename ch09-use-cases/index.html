第 9 章 · Part 4：進階與案例

應用案例集錦

把「看影片」變成資訊來源，而不只是娛樂。

三大典型場景

對象用法
內容創作者 / 行銷快速拆解競品爆紅影片：開場如何抓人、用了什麼廣告梗
開發者 / 技術支援收到使用者回報 bug 的螢幕錄影時，不必反覆拖時間軸，Claude 直接看影片定位問題發生的畫面與步驟
一般知識工作者把長演講、線上課程、會議錄影，變成可搜尋、可摘要的文字筆記

這三類場景的共通點是：它們過去都得靠人工「坐下來把影片看完」才能取得資訊，而 claude-video 把這個步驟自動化成一句 /watch。

真實案例一：用 claude-video 分析介紹 claude-video 的影片

本書 ch05、ch06 引用的素材筆記，本身就是拿 claude-video 分析一支介紹 claude-video 的 GitCovery 頻道影片產出的——某種「吃自己的狗糧」的驗證。實測結果與影片內容高度吻合：

  • yt-dlp 直接抓到 YouTube 原生字幕（182 段），完全沒動用 Whisper，成本趨近於零
  • 該次任務用 --detail transcript，純文字重點整理不需要影格，是最省 token 的做法
  • 過程中也真的踩到「脆弱外部整合」這個已知風險：Windows 主控台 cp950 編碼無法輸出字幕中的零寬空格，一度導致腳本印出逐字稿時 crash，最後改為直接讀取工作目錄的 .vtt 檔繞過

真實案例二：多 Agent 協作工具的介紹影片

第 6 章示範 codex exec 呼叫 claude-video 時，實際處理的影片是一支介紹「Tracer」的 18 分鐘影片——Tracer 是一個開源桌面 workspace，把 Claude Code、Codex、Cursor 等 coding agent 併進同一專案共享 context、互相以 A2A（Agent-to-Agent，跨 agent 通訊協定）通訊與 review，片中示範了 Claude Code 做前端、Codex 做市場情報，協作產出一個 market intelligence dashboard。

這個案例有意思的地方在於：claude-video 從 captions（YouTube 自動字幕，非 Whisper）就完整還原了標題、長度、493 個逐字稿段落與內容摘要——證明只要影片本身有字幕，即使是技術含量較高、術語密集的內容，純文字模式也能準確萃取重點，不需要動用畫面分析。

真實案例三：長篇官方簡報轉可搜尋筆記

另一個實測案例是處理 OpenAI 官方 Codex 入門簡報（53 分鐘、英文原文），claude-video 產出了完整的 523 行中英對照逐字稿。這正對應「一般知識工作者」場景：把一場你沒空即時聽完的長篇簡報，變成事後可以搜尋、可以摘要、可以引用的文字資產，而不是一支只能從頭到尾重播才能找到內容的影片檔。

💡
看完不等於記住——建議固定沉澱成筆記

claude-video 本身只負責「看完影片、回答問題」，不會自動幫你存檔。若想把這些分析結果累積成長期可查詢的知識庫，建議比照本書素材的做法：看完後手動整理成筆記（含逐字稿、核心摘要、與既有筆記的關聯），這樣半年後還能搜得到當初看過什麼、得到什麼結論。

案例背後的共同模式

回頭看這幾個案例，會發現它們其實都遵循同一套判斷邏輯：先問「這個任務要不要看畫面」，再決定 detail 模式；先確認影片有沒有字幕，再決定要不要準備 Whisper 金鑰。這正是第 8 章成本模型的實務落地——技術原理與真實案例互相印證，而不是兩件互相獨立的事。

小結

從「拆解一支介紹自己的影片」到「把 53 分鐘官方簡報變成逐字稿」，claude-video 的應用場景本質上都是同一件事。

把影片從 AI 難以主動取用的被動媒介，變成可以被分析、被搜尋、被引用的資訊來源。
