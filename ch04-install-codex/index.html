第 4 章 · Part 2：安裝與設定

在 Codex 安裝與設定 claude-video

透過 skills registry 安裝，落點是 ~/.agents/skills/，不是 ~/.codex/skills/。

安裝指令

Codex（以及 Cursor、Gemini CLI 等其他 harness）不走 plugin marketplace，而是透過通用的 skills registry 安裝：npx 是隨 Node.js 一起安裝的套件執行工具，執行前要先確認電腦上有裝 Node.js（跑 node --version 看看有沒有回應版本號），沒裝的話先去 nodejs.org 裝好再繼續。

一般終端機（PowerShell）
npx skills add bradautomates/claude-video -g

也可以只安裝給 Codex，不裝到其他 harness：

一般終端機（PowerShell）
npx skills add bradautomates/claude-video -g -a codex

安裝落點：不是 ~/.codex/skills/

這是最容易搞混的一點。npx skills add -g 實際落點是：

安裝目錄結構
~/.agents/skills/watch/
├── .skillignore            171 B
├── SKILL.md             22,075 B
└── scripts/
    ├── watch.py         16,875 B   ← 主控
    ├── whisper.py       17,526 B   ← Groq/OpenAI 純 stdlib client
    ├── frames.py        27,102 B
    ├── download.py       5,634 B
    ├── transcribe.py     2,993 B
    ├── setup.py         12,444 B
    ├── config.py         2,182 B
    └── build-skill.sh    1,430 B

~/.codex/skills/ 這個目錄 Codex 也會讀，但 npx skills add -g 並不寫在那裡——實測本機到現在都沒有這個資料夾。SKILL.md 裡有一段 SKILL_DIR 解析邏輯，就是專門為了讓同一份 skill 在 Claude Code plugin cache、~/.codex/skills、~/.agents/skills 三種不同 layout 底下都能正確定位到 scripts/watch.py。

⚠️
如果你是讓 Claude Code 幫你裝——它裝不了

在 Claude Code 的 auto 權限模式下，npx skills add ... -g 這類「全域安裝」指令會被權限分類器直接擋下（訊息類似「Blocked by classifier」）。這不是 bug，是 Claude Code 刻意把「寫入使用者全域環境」判定為需要人工確認的高風險操作。正確做法：請使用者自己在一般終端機執行這行安裝指令，Claude Code 這一側只負責裝完之後的驗證（見下方）。第 6 章會展示這個限制如何影響「CC 操控 Codex」的實務流程。

驗證安裝成功

安裝完成後，Claude Code 可以（也應該）用唯讀方式確認 skill 真的落地了，而不是假設安裝一定成功：

確認 skill 已安裝
ls ~/.agents/skills/watch/SKILL.md
ℹ️
巢狀目錄雷區

有些 skill 落點是 ~/.agents/skills/skills/<name>/（雙層 skills，例如 whisper-transcribe），有些是 ~/.agents/skills/<name>/（單層，watch 屬於這種）。用 ls 或 find 確認「有沒有裝」時，兩層都要看，否則容易誤判成「沒裝成功」。

「裝了卻用不了」十之八九不是沒裝好，是你在錯的路徑底下找答案。

執行條件

  • 需要 yt-dlp 與 ffmpeg 在 PATH 上
  • 有字幕的公開影片通常可以直接處理，不需要任何金鑰
  • 沒有字幕時，Whisper fallback 需要 GROQ_API_KEY 或 OPENAI_API_KEY；不想設金鑰的話也可以加 --no-whisper 改成只分析畫面、不轉錄語音——但代價是完全沒有逐字稿，如果影片剛好又沒字幕，--no-whisper 配 --detail transcript 這種純文字模式會直接拿到空的結果
  • Windows 環境：所有 python3 … 指令要改用 python；.env 的 chmod 600 檢查在 Windows 上永遠是假警告（下一章有完整說明與替代方案）
💡
沙盒回報的「未安裝」不一定是真的

若你在 Codex 沙盒（限制一個程式能存取哪些檔案、能不能連網路的隔離環境）內探測環境（例如唯讀模式下跑 command -v python），得到「找不到」的結果，不代表實體機器真的沒裝——沙盒看到的 PATH 可能被裁切過。判斷「工具在不在」，一定要在目標 harness 拿到足夠權限後實測，不能只靠受限沙盒的回報下結論。這個坑第 6 章會用一次真實踩雷記錄具體說明。

小結

Codex 的安裝路徑比 Claude Code 多一道手續：指令要在一般終端機跑，不能靠 Claude Code 代勞；落點也不同，是 ~/.agents/skills/ 而不是 plugin cache。理解這兩個差異，就能避免「明明裝了卻用不了」的困惑。裝好之後，下一章開始實戰——先看 Claude Code 這一側最直覺的用法，再進到更有意思的「用 Claude Code 遠端指揮 Codex」模式。
