CC 實務：/watch 指令完整教學

在 Claude Code 裡，claude-video 是一個 plugin，裝好之後只要一句 /watch 就能讓 Claude 真的「看」一支影片。這一章從安裝走到實戰，帶你把整條路徑跑一遍。

安裝：兩行指令

claude-video 在 Claude Code 裡是透過 plugin marketplace 安裝的，不需要修改任何設定檔：

Claude Code 對話框
/plugin marketplace add bradautomates/claude-video
/plugin install watch@claude-video

裝完之後，plugin 會落在 ~/.claude/plugins/cache/claude-video/watch/<版本>/skills/watch/。watch@claude-video 這個名字裡，watch 是 skill 名稱，claude-video 是 marketplace 名稱——兩者合起來才是完整的安裝識別碼。

ℹ️
它不是 MCP Server

claude-video 是一個 Agent Skill，不是 MCP server，不需要碰 claude_desktop_config.json。網路上有些教學文章把它誤植為 MCP，安裝前先破除這個迷思，才不會白繞路去改設定檔。

首次執行：setup 精靈

第一次打 /watch 時，skill 會先跑一次 scripts/setup.py 前置檢查，做三件事：

  1. 檢查 ffmpeg／ffprobe／yt-dlp 三個 binary 是否存在，缺的話會印出對應平台的安裝指令——macOS 會自動用 brew 裝；Windows 不會自動安裝，只會印出提示，需要自己用 winget install ffmpeg、pip install yt-dlp 手動補齊
  2. 建立 ~/.config/watch/.env，內容包含 GROQ_API_KEY／OPENAI_API_KEY／WATCH_DETAIL／SETUP_COMPLETE
  3. 詢問你預設要用哪一種 --detail 模式

如果影片本身有原生字幕，其實完全不用填任何金鑰也能跑；只有遇到「沒字幕、需要語音轉文字」的影片，才需要 Whisper API key（建議填 GROQ_API_KEY，比 OpenAI 便宜也快）。

.env 範例
# ~/.config/watch/.env
GROQ_API_KEY=gsk_xxxxxxxxxxxxxxxxxxxxxxxx
WATCH_DETAIL=balanced
SETUP_COMPLETE=true
⚠️
.env 格式雷區

寫 .env 時要注意：= 後面直接接值、不加引號、不加空白、行尾不要放 # 註解、key 不要換行。whisper.py 的 dotenv parser 只做簡單的 partition("=") 加 strip()，不會過濾行內註解，違規會把整串（含註解）當成 key 值，導致認證失敗卻查不出原因。

🪟
Windows 專屬雷：chmod 600 假警告

skill 會在 SessionStart hook 印出「.env permissions 644，應為 600」的警告。實測 chmod 600 在 Windows／Git Bash 環境完全無效——原生 Windows Python 的 os.stat().st_mode 永遠回報 0o666，這條檢查在 Windows 上永遠會觸發假警告，可以放心忽略。真正要鎖權限，改用 Windows 原生的 icacls（管理檔案存取權限的工具，概念上等同 Linux 的 chmod）：

icacls "$env:USERPROFILE\.config\watch\.env" /inheritance:r /grant:r "$env:USERNAME:F" "NT AUTHORITY\SYSTEM:F"

這行指令的意思是：清除從上層資料夾繼承來的權限設定（/inheritance:r），只保留「你自己的帳號」與「SYSTEM 系統帳號」對這個檔案的完整存取權（F = Full control），其他帳號一律看不到、動不了這個檔案。

四種 detail 模式：先決定要不要抽畫面

--detail 決定 claude-video 要不要花 token 去「看」畫面，直接影響成本：

模式抽圖策略適用情境
transcript完全不抽圖，純逐字稿只要文字內容、成本最低
efficient場景感知去重，上限 50 張需要少量畫面佐證
balanced（預設）場景感知去重，上限 100 張一般用途的最佳平衡
token-burner場景感知去重，不設上限需要盡可能完整的畫面覆蓋（成本高，謹慎使用）

成本模型很直覺：有原生字幕的影片全程免費；真正燒錢的是畫面影格的 token，所以只要文字內容就選 transcript，是最省的做法。

有字幕就全程免費，真正燒錢的從來不是影片本身，是你選錯了 detail 模式。

基本用法

Claude Code 對話框
/watch https://www.youtube.com/watch?v=oBuWXUy7stw 這支影片在講什麼？

指令下去之後，claude-video 會依序：yt-dlp 找免費字幕（命中就零成本直接用）→ 沒字幕才 ffmpeg 拆音訊、丟給 Whisper（優先 Groq）→ 若 --detail 不是 transcript，才輪到 ffmpeg 抽關鍵影格並去重（transcript 模式完全跳過這一步）→ 把「（依模式而定的）影格 + 時間戳逐字稿」一起交給 Claude 分析、回答你的問題。

實戰案例：真的看過的兩支影片

筆者的 Obsidian 知識庫裡另外維護了一套 /video-note 個人筆記管線——這是作者自己的筆記工具，跟 claude-video 是兩個獨立專案，讀者不需要另外安裝，這裡提到它只是因為它底層走的正是同一套「找字幕、必要時才轉錄、抽畫面」邏輯。用這套管線實際處理過的案例中，有兩支影片的紀錄特別值得參考（VID-223／VID-208 是筆者筆記庫裡的內部編號，方便對照原始筆記）：

  • VID-223——GitCovery 頻道深度解析 claude-video 專案本身，內容涵蓋開發者背景、去重演算法細節、與其他方案的比較，逐字稿與核心摘要都已收錄進 Obsidian 筆記庫。
  • VID-208——OpenAI 官方 Codex 入門簡報（53 分鐘），示範了長影片、英文原文的處理效果，完整中英對照逐字稿共 523 行。
💡
把結果沉澱成筆記，而不是看完就忘

claude-video 本身只負責「看完影片、回答問題」，不會自動幫你存檔。若想累積成長期可查詢的知識庫，建議比照 /video-note 的做法，看完後手動整理成 Obsidian 筆記（含雙語逐字稿、核心摘要、與既有筆記的關聯），這樣半年後還能搜得到當初看過什麼。

常見問題排解

ℹ️
Windows 中文輸出出現亂碼／編碼錯誤

若在處理中文標題影片時遇到 UnicodeEncodeError（多半是 cp950 編碼問題），設定 $env:PYTHONIOENCODING='utf-8' 後重跑即可解決。

⚠️
下載或轉錄逾時、HTTP 429

Whisper API 有流量限制，短時間內連續處理多支影片可能撞到 429。若使用 Groq 額度用盡，可切換 OPENAI_API_KEY 當備援，或間隔幾分鐘再試。

小結

在 Claude Code 裡用 claude-video，體驗上就是「裝好 plugin、填一次金鑰、之後每次一句 /watch」——最貼近一般使用者的路徑。但 claude-video 並不是 Claude Code 專屬工具，它同樣能裝進 Codex。下一章我們換到 Codex 這一側，而且不是手動打字互動，而是讓 Claude Code 反過來當指揮官，用 codex exec 把任務派給 Codex 執行——這是一條更有意思、也更適合自動化的路徑。
