第 3 章 · Part 2：安裝與設定

在 Claude Code 安裝 claude-video

plugin marketplace 兩行指令，五分鐘內完成，不需要碰任何 MCP 設定檔。

兩行指令

Claude Code 有自己的一套 plugin 系統，概念上跟瀏覽器裝擴充套件、VS Code 裝 extension 很類似：由第三方開發者把功能包裝好，使用者透過一個「市集（marketplace）」來源安裝。claude-video 在 Claude Code 裡就是透過這套 plugin marketplace 機制安裝的：

Claude Code 對話框
/plugin marketplace add bradautomates/claude-video
/plugin install watch@claude-video

第一行把 bradautomates/claude-video 這個 GitHub repo 註冊成一個 marketplace 來源；第二行才是真正的安裝動作。watch@claude-video 這個識別碼要拆開讀：watch 是 skill 名稱，claude-video 是 marketplace 名稱——兩者合起來才是完整的安裝目標，少一半都裝不起來。

ℹ️
前提：Claude Code 版本要夠新

/plugin 是 Claude Code 相對後期才加入的功能。如果打 /plugin marketplace add 出現「找不到指令」，先確認 Claude Code 是不是太舊——更新到最新版通常就能解決。

兩行指令就能裝完，不代表背後的東西很簡單——複雜的是上一章拆解過的那條省錢 pipeline，不是安裝這個動作本身。

安裝落點

裝完之後，plugin 實體檔案會落在：

安裝目錄
~/.claude/plugins/cache/claude-video/watch/<版本>/skills/watch/

本機實測版本為 0.2.0。這個目錄底下就是 SKILL.md 與 scripts/（watch.py、whisper.py、frames.py、download.py、setup.py 等），跟 Codex 那一側的目錄結構是同一套邏輯，只是掛載路徑不同（下一章會對照）。

首次執行：setup 精靈

裝好 plugin 之後，第一次打 /watch 會自動觸發 scripts/setup.py 前置檢查，依序做三件事：

  1. 檢查 ffmpeg／ffprobe／yt-dlp 三個 binary（可執行程式）是否存在，缺的話印出對應平台的安裝指令（macOS 甚至會自動用 brew 裝）
  2. 生成 ~/.config/watch/.env（權限預期 0600），內容包含 GROQ_API_KEY／OPENAI_API_KEY／WATCH_DETAIL／SETUP_COMPLETE
  3. 詢問你預設要用哪一種 --detail 模式（transcript／efficient／balanced／token-burner，第 8 章有完整成本對照）
ℹ️
0600 是 Unix 權限模型，Windows 沒有完全對應的機制

「權限預期 0600」指的是類 Unix 系統的檔案權限位元（只有擁有者能讀寫這個檔案）。Windows 原生檔案系統沒有這套模型，就算腳本嘗試設定，實際效果通常只是切換「唯讀」屬性，並不是真的限制其他使用者帳號存取——如果你在共用電腦或多使用者環境操作，.env 裡的金鑰安全性不能只靠這個機制把關。

ℹ️
有字幕的影片，其實不用填任何金鑰

只有遇到「沒字幕、需要語音轉文字」的影片，才需要 Whisper API key。建議優先填 GROQ_API_KEY，比 OpenAI 便宜也快，OpenAI 留著當備援。

驗證安裝成功

安裝完成後，可以直接用一支短影片測試整條 pipeline 是否跑得通：

Claude Code 對話框
/watch https://www.youtube.com/watch?v=oBuWXUy7stw 這支影片在講什麼？

如果回傳的內容包含正確的標題、長度、以及有條理的摘要，代表 yt-dlp、ffmpeg、（若有觸發）Whisper 三個依賴都正常運作。第 5 章會用真實影片走一遍完整的實戰案例，包含常見錯誤排解。

小結

Claude Code 這一側的安裝路徑是三個環境裡最簡單的：不用碰終端機、不用裝 Node 套件，兩行斜線指令就結束。下一章換到 Codex，安裝方式和落點都不一樣，而且會踩到一個 Claude Code 自己的權限分類器限制——值得單獨一章講清楚。
